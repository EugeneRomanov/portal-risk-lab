# Лаборатория нестабильных порталов

Интерактивный инструмент смотрителя лаборатории: показывает порталы, рассчитывает риск, рекомендует действие и не допускает нелогичные операции без объяснения причины.

## Ссылки

- [Рабочее приложение](https://portal-risk-lab.romanov6229.chatgpt.site)
- [GitHub-репозиторий](https://github.com/EugeneRomanov/portal-risk-lab)

## Возможности

- реестр из семи порталов с поиском и фильтрацией;
- прозрачный расчёт риска из стабильности, энергии, срочности и наличия существ;
- действия «Стабилизировать», «Закрыть», «Отправить наблюдателя» и «Под вопросом»;
- предупреждение при закрытии портала, внутри которого остались существа;
- журнал успешных и отклонённых операций;
- итоговая сводка и приоритизация критических порталов;
- сохранение состояния в `localStorage`, пустое и ошибочное состояния;
- встроенный экран AI Worklog;
- пять автоматических тестов доменной логики.

## Локальный запуск

Требования: Node.js 22.13+ и pnpm.

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`.

## Проверка

```bash
pnpm test

```

### Проверка за одну минуту

1. Выберите критический «Разлом Тихой Луны» и изучите объяснение риска.
2. Попробуйте отправить наблюдателя — приложение объяснит запрет и запишет попытку в журнал.
3. Стабилизируйте портал — риск снизится, а запас времени увеличится.
4. Попробуйте закрыть портал с существами — появится обязательное предупреждение.
5. Откройте вкладки «Журнал» и «AI Worklog».

## Формула риска

```text
риск = (100 − стабильность) × 0.45
     + энергия × 0.30
     + срочность × 0.20
     + наличие существ × 0.05
```

Срочность переводит оставшееся время в шкалу 15/45/75/100. Наличие существ добавляет 60 баллов до применения веса. Итог ограничивается диапазоном 0–100.

Пороги: низкий — до 35; средний — 35–59; высокий — 60–79; критический — от 80.

## Архитектура

- `lib/portal-engine.ts` — чистые функции расчёта риска, рекомендаций, валидации и переходов состояния;
- `lib/seed-data.ts` — демонстрационный набор;
- `app/page.tsx` — рабочая поверхность, журнал и AI Worklog;
- `tests/portal-engine.test.ts` — тесты ключевых правил.

Секреты и внешние API не используются.

## AI Worklog

Полный журнал встроен в приложение на вкладке **AI Worklog**. В нём отдельно показаны роль человека как владельца продуктовых решений и приёмки, вклад AI как инструмента анализа и реализации, время, ключевые промпты, корректировки и возможные улучшения.
